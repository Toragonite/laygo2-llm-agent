# 측정 프로토콜 (Phase 3 baseline)

사용자 결정 (2026-09-30). 바꾸면 다른 실험 조건이므로 날짜와 함께 기록한다.

## 1. 수정 지시 수준
| 수준 | 지시에 담는 것 | 예 |
|---|---|---|
| L1 결과 | 도구 출력만 (에러 메시지, DRC 규칙 이름, LVS net 수) | "LVS 실패, net 4/6" |
| L2 진단 | 무엇이 왜 틀렸는지. 고치는 방법은 말하지 않음 | "A와 OUT이 같은 열을 써서 합선됨" |
| L3 방향 | 어떻게 고칠지. 구체적인 값은 주지 않음 | "route_via_track으로 옆 열로 옮겨라" |
| L4 구체 | 열 번호, 좌표, 배선 계획 | "경계 열 4번에 놓아라" |

- **baseline 상한은 L3.** L4 지시는 쓰지 않는다. 쓰게 되면 그 실행은 baseline에서 제외하고 따로 표시한다.
- 지시마다 `chat.py`에서 `p: [L2] ...`, `r: [L3] ...`처럼 수준을 적는다. 수준 태그는 LLM에 보내지 않는다.
- 코드 블록과 golden 코드는 어떤 수준에서도 주지 않는다.
- 도구 출력을 매 라운드 자동으로 붙여 보내는 방식은 쓰지 않는다 (자동 피드백 = 개선 단계, 범위 밖).

## 2. 실패 유형
| 유형 | 뜻 | 예 |
|---|---|---|
| A. API 오용 | laygo2 함수의 반환값·인자·헬퍼를 잘못 씀 | 반환값 개수 오해, 핀에 placement 헬퍼 사용, grid 섞어 쓰기 |
| B. 회로 해석 오류 | 넷리스트의 연결을 레이아웃 요소로 잘못 옮김 | 레일이 아닌 단자에 tie, 트랜지스터·dict 대응 혼동, 연결 누락 |
| C. 배선 충돌 | 서로 다른 net이 같은 열·행을 쓰거나 다른 net의 핀 위를 지나 합선 | 게이트·드레인 같은 열, stub 겹침 |
| D. 기하 오해 | 명령이 실제로 어떤 도형을 그리는지 잘못 앎 | 행이 다른 두 점을 `route()`로 이어 큰 사각형 |
| E. 간격 위반 | 연결은 맞지만 도형이 너무 가까움 (DRC) | li.3 간격 |

- **원인이 둘 이상이면 모두 기록한다** (다중 라벨). 예: `/label 3 A,C`.
- 라운드 0 = `generate.py`의 처음 6턴 결과, 1부터 = 수정 지시 후 결과.
- 라벨은 실패한 라운드마다 붙인다 (`chat.py`의 `/label`).

## 3. 실행 규칙
- 셀당 수정 지시 상한 8개. 8개 안에 통과하지 못하면 실패로 기록한다.
- 한 지시 = 한 메시지 (스크립트 모드에서는 `---` 줄로 구분).
- 기록: 모델, temperature, 컨텍스트 버전, 시도 번호, 날짜, 지시 작성자 (`meta.json`, `chat.json`).
